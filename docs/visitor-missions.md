# Visitor missions

## Summary and experience

The former Side Quests entry now opens **Your missions**: optional challenges for the person visiting the portfolio. Career chapter discovery remains in the separate file and menu artifacts.

Visitors can assemble a learning loop, review an unsupported AI claim, and interpret a JEV research result. Each mission gives a scenario, a concrete decision at each step, feedback for incorrect attempts, and a completion state. A wrong answer does not advance the mission. A case link appears after success, but following a link never awards completion. These are simplified scenarios, not proficiency assessments or production outcomes.

The board shows completed missions out of three. Visitors can play in any order, replay completed missions and reset all progress. There is no timer, account, external scoring or analytics. English and Spanish share the same mission IDs and rules.

## Technical overview

- `src/components/VisitorMissions.tsx`: board, scenario flow, feedback, focus and contextual links.
- `src/lib/visitor-missions.ts`: mission definitions, answer validation, saved completion filtering and a React external store backed by `sessionStorage`.
- `PortfolioDialogs.tsx`: retains the native dialog, profile and close/navigation contract; delegates the mission content.
- `SceneDiscoveries.tsx` and `Observatory.tsx`: visitor-oriented entry labels.
- `portfolio-dialogs.css`: existing paper colors, typography, progress and responsive layouts; respects paused/reduced motion.
- `src/i18n/es.json`: Spanish copy; locale modules remain generated by the existing build.

No database, API, credentials or new dependencies. The versioned session key `tg-visitor-missions-v1` contains only completed IDs. Progress survives reload, same-tab case visits and language changes during that tab's session. Invalid saved data is filtered. When storage is unavailable, the store works in memory for the current page lifetime; the UI explains the limitation. Partial attempts restart after page navigation.

## Validation

`tests/visitor-missions.test.mjs` exercises all correct/incorrect choices, partial and final steps, invalid inputs, corrupted/duplicate saved IDs, EN/ES rule parity, store notifications, reset and blocked storage.

Run `npm test`, `npm run lint`, `npm run build`, and `npm run typecheck`. Browser verification covers the actual board and challenge flow, persistence, language switching, dismissal/focus, and narrow layouts.

Verified on 2026-10-17: all 23 tests, lint, production build and typecheck passed; the local route verifier passed 31 checks. Chrome checks completed all three missions, exercised incorrect-answer feedback, preserved completion through reload and EN/ES switching, reset progress, activated choices with Enter, dismissed with Escape, restored entry focus, and retained quick-profile fragment navigation. At a 320px viewport, both the board and a Spanish mission fit without horizontal overflow; headings clear the sticky dialog bar.

## Operations and rollback

The mission board runs entirely in the browser without services or environment variables. Revert the feature commit to restore the former dialog; the unused session key can safely remain until the session ends. If mission semantics change later, version the storage key so old completions do not count for a different challenge.
